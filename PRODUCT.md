# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Knowledge workers who keep many tabs open in one Chrome window (work, research, documentation, social, shopping mixed together) and lose track of them. They open the side panel several times a day to put the window back in order, then go back to their work. Grouping tabs by hand in Chrome is slow enough that they otherwise don't do it.

## Product Purpose

autoGroup is a Chrome MV3 extension that sorts the ungrouped tabs of the current window into Chrome tab groups, by site or by topic with an AI the user chooses. It shows an editable proposal first and moves nothing until the user presses **Apply**; **Undo** puts every tab back. Success: the user gets a sensible proposal in seconds, corrects it with a few edits, applies it, and trusts the extension enough to use it daily.

## Positioning

The owner does not claim a mechanism competitors couldn't copy: autoGroup's position is being first with this combination on Chrome. Future work must not invent a uniqueness claim. The factual traits it can describe are: the user picks the AI (built-in Chrome model, a local model, an OpenAI-compatible service, optional fast classifier); preview before anything moves, with Undo; no developer servers or analytics; user-defined categories with descriptions and sites.

## Operating Context

- Lives in Chrome's **side panel**, beside the page the user is browsing; opened by the toolbar icon or `Alt+Shift+G`. Also an options page and a first-run onboarding guide.
- Core loop: Organize → review/edit proposal (rename, recolor, move, remove, discard group, save AI group to list) → Apply → optional Undo.
- Two modes: *By site* (instant, local) and *With AI* (topic). Fallback chain Classifier → Generator → by site, so a proposal always arrives; the by-site proposal is visible while the AI works (**Use this**).
- Secondary jobs in the panel: duplicate tabs, inactive tabs (not opened for a week), jump/mute/close tabs, collapse or close groups, drag and drop, A–Z sorting, settings backup.
- Automatic grouping places tabs from category sites into their group without opening the panel (can be turned off).

## Capabilities and Constraints

- Stack: WXT 0.21, React 19, TypeScript 5.9; logic in the service worker behind the Organizer; UIs talk to it only through `remoteOrganizer`.
- Scope limits: current window only; never touches pinned tabs, already-grouped tabs, Chrome pages or excluded domains; existing groups are never renamed. Not yet: topic auto-grouping while browsing, reorganizing grouped tabs, multi-window, drag and drop inside the proposal preview.
- UI is Material 3 via `src/ui/md3-tokens.css` + `base.css`, Material Symbols icons via `src/ui/Icon.tsx`; no CSS framework.
- All UI text goes through `t(key)` and must exist in all five locales (en, it, es, fr, de); interface follows Chrome's language. Strings must survive German/French length.
- The side panel is narrow: every panel surface must work at roughly 320–400px wide.
- Host permissions are optional and requested synchronously in the click handler; any change to permissions or data sent to providers updates the privacy docs.
- Chrome Web Store listing rules: no lists of brand/provider names in store texts (rejected 5 October 2026 for excessive keywords); describe options by what they do.

## Product Principles

1. **The user stays in control.** Propose, never impose: preview, edit, Apply, Undo.
2. **Always a result.** A proposal arrives even when the AI fails, and the panel says why.
3. **Say what leaves the computer.** Data sent to a provider is minimal and stated plainly.
4. **Fast in, fast out.** The panel is a quick tidy-up between tasks, not a place to stay.

## Accessibility & Inclusion

- Target WCAG 2.2 AA in the panel, options and onboarding: contrast, full keyboard operation (including alternatives to drag and drop), screen reader labels.
- Five interface languages; layouts must tolerate longer translations.
